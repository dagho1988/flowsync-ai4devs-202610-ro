# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository overview

FlowSync is a course exercise project (LIDR AI4Devs, module 1 "harness engineering"). It is a TypeScript monorepo with two independent npm packages — no root `package.json`, no workspaces:

- `backend/` — AdonisJS 7 JSON API (Lucid ORM on SQLite, VineJS validation, token auth). Already implements signup/login/profile/logout.
- `frontend/` — React 19 + Vite 8 SPA with React Router, Tailwind v4 and shadcn/ui. Implements signup, login and a protected profile page.

The root `README.md` is a generated exercise brief (do not edit by hand). `prompts.md` is a template where the student logs every prompt they launch. Docs and commit messages in this repo are written in Spanish.

Requires Node.js v24+.

## Commands

Run each package from its own directory.

### Backend (`backend/`, serves on http://localhost:3333)

```bash
npm install
cp .env.example .env && node ace generate:key   # first-time setup
node ace migration:run                            # creates tmp/db.sqlite3 and regenerates database/schema.ts
npm run dev          # node ace serve --hmr
npm test             # node ace test (Japa)
node ace test --files=tests/functional/foo.spec.ts   # single test file
node ace test functional                             # single suite (unit | functional)
npm run lint         # eslint
npm run typecheck    # tsc --noEmit
npm run format       # prettier (@adonisjs/prettier-config)
```

Test suites are defined in `adonisrc.ts`: `tests/unit/**/*.spec.ts` and `tests/functional/**/*.spec.ts` (the functional suite boots the HTTP server). No test files exist yet — only `tests/bootstrap.ts`. `.env.test` sets `SESSION_DRIVER=memory`.

### Frontend (`frontend/`, serves on http://localhost:5173)

```bash
npm install
npm run dev
npm run build        # tsc -b && vite build (this is also the typecheck)
npm run lint         # oxlint
npm run format       # prettier --write src (format:check to verify)
```

Prettier config is `frontend/.prettierrc.json` (no semicolons, single quotes, trailing commas). A `PostToolUse` hook (`.claude/hooks/format-frontend.mjs`) auto-formats any file edited under `frontend/src/`, so don't reformat by hand. No test runner is configured in the frontend.

## Frontend architecture

- `@/*` alias → `frontend/src/*` (set in `vite.config.ts` and both tsconfigs). shadcn components live in `src/components/ui/` and are generated with `npx shadcn@latest add <name>` (config in `components.json`); `cn` comes from shadcn's `cn` package.
- `src/lib/api.ts` is the only place that calls the backend: it unwraps `{ data }`, throws `ApiError { status, errors }` (status 0 = network failure). Base URL is `VITE_API_URL`, defaulting to `http://localhost:3333/api/v1`.
- `src/lib/errors.ts` maps `ApiError`s to Spanish UI messages; `src/lib/auth.tsx` (`AuthProvider` / `useAuth`) keeps the token in `localStorage` (`flowsync.token`).
- Routes (`src/App.tsx`): `/login`, `/signup` (guest only), `/profile` (behind `RequireAuth`); anything else redirects to `/profile`.

## Project harness (`.claude/`, `.mcp.json`)

- Skills: `/commit` (conventional commit from staged changes) and `/priority-ticket` (pulls the top-priority Jira ticket in «Por hacer», plans it, moves it to «En curso»).
- Agent: `adversarial-reviewer` reviews a PR (number or URL) and reports findings by severity; it never edits.
- `.mcp.json` registers the Atlassian MCP server (Jira tickets like `FLOW-2`).
- `AGENTS.md` is a link to this same file (for other agents), so editing either one updates both.

## Backend architecture

- **Routing** (`start/routes.ts`): everything lives under `/api/v1`. Routes reference controllers through the generated map `controllers.X` from `#generated/controllers`, not via direct imports.
  - `POST /api/v1/auth/signup` → `NewAccountController.store`
  - `POST /api/v1/auth/login` → `AccessTokensController.store`
  - `GET /api/v1/account/profile` → `ProfileController.show` (auth required)
  - `POST /api/v1/account/logout` → `AccessTokensController.destroy` (auth required)
- **Generated code** — do not edit by hand:
  - `.adonisjs/` (controllers map, Tuyau route registry/types) is regenerated by the `indexEntities` and `generateRegistry` hooks in `adonisrc.ts` when the dev server/build runs.
  - `database/schema.ts` is regenerated by `node ace migration:run`. Models extend these generated schema classes (e.g. `User extends compose(UserSchema, withAuthFinder(hash))`) instead of declaring columns themselves. Customize generation through `database/schema_rules.ts`.
- **Path aliases**: imports use the `#alias/*` subpath imports declared in `backend/package.json` (`#models/*`, `#validators/*`, `#transformers/*`, etc.); prefer them over relative paths.
- **Response shape**: `providers/api_provider.ts` adds `ctx.serialize()`, which wraps the payload in `{ data: ... }`. Controllers return `serialize(SomeTransformer.transform(model))`; transformers (`app/transformers/`) whitelist exposed fields (`UserTransformer` → `id, fullName, email, createdAt, updatedAt, initials`).
- **Auth**: default guard is `api` (opaque access tokens stored in `auth_access_tokens`, sent as `Authorization: Bearer <token>`). A `web` session guard is also configured but unused by routes. `silent_auth_middleware` runs globally; the named `auth` middleware protects the `account` group.
  - Signup and login both return `{ data: { user, token } }`.
- **Validation** (`app/validators/user.ts`): signup requires `email`, `password` (8–32 chars) **and `passwordConfirmation`** (must match); `fullName` must be present but may be `null` (omitting it is a 422 `required`); email must be unique (422, rule `database.unique`). Login takes `email` + `password`. Validation failures return 422 with `{ errors: [{ field, rule, message }] }`; bad credentials (`User.verifyCredentials`) return **400** `{ errors: [{ message }] }` with no `field`; a missing/invalid token returns 401.
- **JSON everywhere**: `force_json_response_middleware` forces `Accept: application/json`, so errors are always JSON.
- **CORS**: all origins allowed in development (`config/cors.ts`), credentials enabled.

## Process rules

Follow these for every task that changes code:

1. **New branch before touching code.** Never commit on `main` or on the branch you started from. Name it `feat/<TICKET>-<short-slug>` (or `fix/...`, `chore/...`) when there is a Jira ticket, e.g. `feat/FLOW-2-login`.
2. **When done, commit with `/commit`.** Stage the relevant files yourself, then run the `/commit` skill. Don't write commit messages by hand.
3. **Open the pull request with `gh pr create`** against `main`. The body lists the ticket key and its acceptance criteria, and says how each one is covered.
4. **Then run the `adversarial-reviewer` subagent on that pull request.** Fix any `CRÍTICO` or `ALTO` findings on the same branch, commit them with `/commit`, and push.
5. **In the chat, reply with only the pull request URL.** No summary, no list of changes: the PR body is where that goes.
